서버 실험실

Tiny 서버의 기능과 한계를 브라우저에서 직접 확인하는 페이지예요. 개발자 도구의 Network 탭을 열어 두고 보세요.

1. 블로킹: 느린 CGI

/cgi-bin/slow?sec=5를 새 탭으로 열고, 5초가 지나기 전에 이 탭에서 홈을 새로 열어 보세요. 서버가 CGI가 끝나기를 wait로 기다리는 동안 다른 요청도 모두 멈춰요.

버튼을 누르면 slow(3초)와 home.html을 동시에 요청하고 각각 걸린 시간을 보여 줘요.

2. 블로킹: 큰 파일

big-photo.jpg (약 5MB). Network 탭에서 스로틀링을 "Slow 4G"로 두고 받는 동안 다른 탭에서 홈을 열어 보세요. 서버가 응답을 끝까지 쓰기 전에는 다음 연결로 넘어가지 않아요.

3. Keep-alive 없음

홈을 새로고침하고 Network 탭에서 Connection ID 열을 켜 보세요(열 이름에서 오른쪽 클릭). 파일마다 ID가 다르면 요청마다 새 TCP 연결을 연 거예요. 응답 헤더는 항상 HTTP/1.0, Connection: close예요.

4. 에러 응답

  • 없는 페이지 → 404
  • 권한 없는 파일 (secret.html) → 403
  • 백엔드에 없는 파일 → 백엔드가 돌려준 404를 그대로 전달
405(정적 파일에 POST), 413(8KB 초과 body), 501(PUT)를 요청해서 상태 코드를 보여 줘요.

5. 리버스 프록시와 라운드로빈

요청마다 응답한 백엔드를 보여 줘요.

백엔드를 하나 끄면(kill) 그 차례의 요청은 502가 나요. 헬스 체크나 재시도가 없기 때문이에요.
